# 经营单据与结算服务

本地可运行的多租户经营单据服务。当前支持受理订单、按标识读取订单、登记收款并核对未收金额；数据落本地 SQLite 文件库，服务为单进程 HTTP 服务。

## 环境与安装

- Python 3.11
- `python3 -m venv .venv && . .venv/bin/activate && pip install -e .`

## 启动

- `python3 -m app.entry --port 8000`
- 健康检查：`GET /health`

## 测试

- `pytest -q`
- 静态检查：`ruff check .`

## 已有公开接口

- `POST /orders`：受理订单（支持可重放接收）。请求字段 `tenant`、`order_id`、`amount_cents`、`currency`、`idempotency_key`、`request_fingerprint`；后两者为非空字符串：
  - 幂等键唯一范围为（租户, 幂等键），与订单标识的（租户, 订单标识）唯一性相互独立。
  - 首次受理：201，新建订单并登记幂等记录。
  - 同键同指纹重放：201，响应头 `X-Idempotency-Replay: true`，不新建订单、不改变订单与收款，返回首次受理的订单对象快照。
  - 同键不同指纹：422（幂等键被用于不同业务内容），不覆盖首次受理的订单、金额、币种或收款。
  - 订单标识重复（即便使用新幂等键）：409，不改变已存在单据；与 422 明确可区分。
  - 缺少幂等键或指纹（含空串）：400，不落任何数据。
  - 受理为单事务原子写入，并发下同键仅一笔真正受理；提交前崩溃不留下任何记录，重启后用同键重试等价于首次受理。
- `GET /orders/{order_id}`：按标识读取订单。租户通过请求头 `X-Tenant` 传入；不存在返回 404；跨租户读取返回 404（不泄漏对象是否存在）。
- `POST /orders/{order_id}/payments`：登记收款。请求字段 `amount_cents`；超过未收金额返回 409；成功返回 200 与订单的 `paid_cents`、`outstanding_cents`，并附带服务分配的收款记录标识 `payment_id`（同租户内唯一、稳定不变、不由调用方指定）。收款登记不经过幂等键机制。
- `POST /payments/{payment_id}/reversals`：对某笔已登记收款发起冲正（抵回）。请求字段 `reversal_id`、`request_fingerprint`，均为非空字符串；租户经请求头 `X-Tenant` 传入：
  - 冲正标识唯一范围为（租户, 冲正标识），与收款记录标识相互独立。
  - 首次冲正：200，订单已收减少相应金额、未收相应回升；未收清零（已收回到全额应收）为 `settled`，否则回到 `accepted`；返回首次冲正结果快照（含冲正金额与冲正后订单对象）。
  - 同标识同指纹重放：200，响应头 `X-Idempotency-Replay: true`，不重复抵回任何金额，返回首次冲正结果快照。
  - 同标识不同指纹：422（冲正标识被用于不同业务内容），不覆盖首次冲正记录或已登记收款。
  - 对已冲正收款换用新冲正标识再次冲正：409（收款已处理；冲正本身不可再被冲正），与 422 明确可区分。
  - 缺少冲正标识或指纹（含空串）：400，不落任何数据；收款记录不存在或跨租户：404，不改变订单与收款。
  - 冲正为单事务原子写入：任一时刻应收恒等于已收加未收；同一收款的并发冲正仅一笔真正生效（其余按重放或 409 给出确定结论）；提交前崩溃不留记录，重启后用同一冲正标识重试等价于首次冲正。
- `GET /health`：返回服务与数据库状态。

## 数据与配置

- 数据库文件默认 `var/app.sqlite`（不入库）。
- 环境变量：`APP_DB`（数据库路径）、`APP_PORT`（监听端口）、`APP_TENANT_HEADER`（默认 `X-Tenant`）。

## 当前限制

- 单进程运行，单库写入，未做连接池与写并发调优。
- 租户通过请求头声明，未接入真实身份提供方。
- 无缓存层；批量导入只支持小样本同步方式。
- 收款只支持整单登记，支持对单笔收款做一次性冲正抵回；未实现分期、退款与对账。
