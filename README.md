# 经营单据与结算服务

本地可运行的多租户经营单据服务。当前支持单笔与批量受理订单、按标识读取订单、登记收款并核对未收金额；数据落本地 SQLite 文件库，服务为单进程 HTTP 服务。

## 环境与安装

- Python 3.11
- `python3 -m venv .venv && . .venv/bin/activate && pip install -e .`

## 启动

- `python3 -m app.entry --port 8000`
- 健康检查：`GET /health`

## 测试

- `pytest -q`
- 静态检查：`ruff check .`

## 已有公开接口

- `POST /orders`：受理订单（支持可重放接收）。请求字段 `tenant`、`order_id`、`amount_cents`、`currency`、`idempotency_key`、`request_fingerprint`；后两者为非空字符串：
  - 幂等键唯一范围为（租户, 幂等键），与订单标识的（租户, 订单标识）唯一性相互独立。
  - 首次受理：201，新建订单并登记幂等记录。
  - 同键同指纹重放：201，响应头 `X-Idempotency-Replay: true`，不新建订单、不改变订单与收款，返回首次受理的订单对象快照。
  - 同键不同指纹：422（幂等键被用于不同业务内容），不覆盖首次受理的订单、金额、币种或收款。
  - 订单标识重复（即便使用新幂等键）：409，不改变已存在单据；与 422 明确可区分。
  - 缺少幂等键或指纹（含空串）：400，不落任何数据。
  - 受理为单事务原子写入，并发下同键仅一笔真正受理；提交前崩溃不留下任何记录，重启后用同键重试等价于首次受理。
- `POST /orders/batch`：批量受理订单（可重放、可续跑）。请求字段 `batch_id`、`request_fingerprint`（批次指纹，由调用方对整批内容做稳定摘要）、`lines`（非空行数组，每行字段同 `POST /orders`，含各自的 `idempotency_key` 与 `request_fingerprint`）。批次租户取首行租户，租户缺失/与批次不一致的行按行级不合法拒绝。
  - 批次标识唯一范围为（租户, 批次标识），与每行幂等键、订单标识的唯一性相互独立。
  - 批次按指纹判定重复：同批次标识同指纹为重放，200、响应头 `X-Idempotency-Replay: true`，不重复受理任何一行，返回首次结果清单；同批次标识不同指纹为 422，不覆盖首次导入的任何订单与行结果（与行级 422、订单重复 409 明确可区分）。缺 `batch_id`/`request_fingerprint`（含空串）或空行列表为 400，不落任何数据。
  - 逐行受理、各自独立事务：行级结论为 `accepted`/`replayed`/`rejected_invalid`/`rejected_fingerprint`/`rejected_duplicate`，按 `line_no` 定位；行级拒绝只影响本行，不回滚其他行、不改已有订单与收款。`result` 汇总为 `success`（无拒绝）/`partial`（有合格有拒绝）/`failed`（全部不合格）。
  - 计数闭合：`counts` 中 accepted + replayed + 各拒绝数 = `total_lines`；成功与重放行与实际落库订单一一对应。
  - 可续跑：中断后已逐行提交的行保持已受理，未处理行无半笔数据；以同一（租户, 批次标识）同指纹重新提交，只补做未受理行（响应 `resumed: true`，已受理行带 `replayed: true`），最终结论与一次性完整导入一致；完成后再提交即纯批次重放。
  - 并发下同一（租户, 批次标识）只有一批真正导入，其余同指纹按重放、异指纹按 422 给出确定结论；每笔订单与其行级幂等记录、行结论在同一事务内原子提交，提交前崩溃不留半笔数据。
- `GET /orders/{order_id}`：按标识读取订单。租户通过请求头 `X-Tenant` 传入；不存在返回 404；跨租户读取返回 404（不泄漏对象是否存在）。
- `POST /orders/{order_id}/payments`：登记收款。请求字段 `amount_cents`；超过未收金额返回 409；成功返回 200 与订单的 `paid_cents`、`outstanding_cents`，以及服务分配的收款记录标识 `payment_id`。收款登记不经过幂等键机制，`payment_id` 不由调用方指定。
- `GET /payments/{payment_id}`：按标识读取收款记录（含 `status`：`active`/`reversed`）。租户通过请求头 `X-Tenant` 传入；不存在与跨租户均返回 404。
- `POST /payments/{payment_id}/reversal`：冲正一笔已登记收款。请求字段 `reversal_id`、`request_fingerprint`（均为非空字符串，后者由调用方对冲正内容做稳定摘要得到）：
  - 冲正标识唯一范围为（租户, 冲正标识），与 `payment_id` 相互独立；同一标识只允许生效一次。
  - 首次冲正：200，收款置为 `reversed`，订单已收减少、未收回升；未收清零为已结清，否则回到受理态；响应为冲正结果快照（含冲正后的订单对象）。
  - 同标识同指纹重放：200，响应头 `X-Idempotency-Replay: true`，不重复抵回金额，返回首次冲正的结果快照。
  - 同标识不同指纹：422（冲正标识被用于不同业务内容），不覆盖首次冲正记录与已登记收款。
  - 对已冲正收款再次冲正（含换新冲正标识）：409（已处理），冲正本身不可再被冲正；与 422 明确可区分。
  - 缺少冲正标识或指纹（含空串）：400，不落任何数据。
  - 收款不存在与跨租户冲正：404，不改变订单与收款，也不消耗冲正标识。
  - 冲正为单事务原子写入：两个对同一收款的并发冲正仅一笔真正生效；提交前崩溃整体回滚，重启后以同一冲正标识重试结论与未崩溃时一致。
- `GET /health`：返回服务与数据库状态。

真实 HTTP 调用的端到端演示（临时库 + 真实 uvicorn 进程，覆盖首次受理、重放、指纹冲突、订单重复、缺参数、并发唯一受理、提交前崩溃恢复）：

## 批量受理演示

真实 HTTP 调用的端到端演示（临时库 + 真实 uvicorn 进程，覆盖完整导入、部分失败与行级各拒绝、批次重放、批次指纹冲突、缺批次参数、中断续跑、提交前崩溃恢复、同指纹并发唯一导入）：

## 数据与配置

- 数据库文件默认 `var/app.sqlite`（不入库）。
- 环境变量：`APP_DB`（数据库路径）、`APP_PORT`（监听端口）、`APP_TENANT_HEADER`（默认 `X-Tenant`）。

## 当前限制

- 单进程运行，单库写入，未做连接池与写并发调优。
- 租户通过请求头声明，未接入真实身份提供方。
- 无缓存层；批量导入只支持小样本同步方式。
- 收款支持整单登记与按收款记录冲正，未实现分期与对账。
