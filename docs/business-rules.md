# 业务规则

## 订单与收款

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 收款计划

- 收款计划仅允许在订单尚未收到任何款项时建立；已登记收款的订单、重复建立、期次标识重复、任一期金额不大于零、各期金额之和不等于订单金额的请求一律整体拒绝，不写入任何期次。
- 期次标识在（租户， 订单）内唯一；计划按期次建立顺序推进。
- 取消计划同样仅限订单未收到任何款项时；取消后订单回到无计划状态，可重新建立。建立与取消均不改变订单的未收金额、已收金额与状态。
- 存在计划的订单登记收款时，一次登记金额必须等于从当前未收讫期次起若干个连续期次的剩余金额合计（一次收满一期或多期，可跨期，不留不足一期的零头）；不满足时整体拒绝（409），订单金额与各期进度均不改变。
- 每期累计已收满本期金额即收讫；任意时刻各期已收之和等于订单已收金额，已收讫各期金额之和等于订单已收金额。

## 退款单
- 退款请求标识（refund_request_id）由客户端提供，在（租户, 请求标识）内唯一，用于请求去重；它与订单标识、退款单业务标识是三个相互独立的身份，不得用订单标识充当请求去重身份。
- 退款金额必须为大于零的整数，币种沿用原订单币种。
- 不允许对不存在、不属于本租户或已被拒绝（order.status='rejected'）的订单发起退款；跨租户一律按不存在处理。
- 同一（租户, 退款请求标识）重复提交：
  - 内容（订单、金额）与首次一致：返回首次受理的退款单，不重复受理、不重复占额（首次 201，重放 200）。
  - 内容与首次不同（指向不同订单或不同金额）：以 request_conflict 拒绝，首次单据的金额与状态不得被改写。
- 退款单生命周期：accepted（受理）→ completed（完成）/ rejected（拒绝）；accepted 可退回补件进入 awaiting_supplement，补件通过后回到 accepted。
  - 受理：金额计入订单的未决退款占用 pending_refund_cents，并阻止会破坏守恒的后续退款。
  - 退回补件：仅 accepted 单据可退回，进入 awaiting_supplement；占用额保留不变。必须给出补件事由码（missing_proof、wrong_account、amount_mismatch）与非空说明。等待补件期间以完全相同的事由与说明重复发起视为同一操作重放，不新增退回记录；事由或说明与首次不同返回 409，首次退回记录的事由与说明不得被改写。已完成或已拒绝的单据不能退回（409）。
  - 补件提交：awaiting_supplement 单据可提交新的退款金额（大于零的整数，币种沿用订单）继续审核；通过后回到 accepted，并以新金额重算本单占用（新金额小于原占用时立即释放超出部分）。守恒在计入本单占用的前提下校验：将本单占用替换为新金额后，refunded_cents + pending_refund_cents 不得超过 paid_cents；不满足返回 409，退款单仍为 awaiting_supplement，金额、占用与记录均不改变。补件通过后以相同新金额重复提交按重放处理，以不同金额提交返回 409。
  - 完成：占用额转入累计已退 refunded_cents，冲减净额并按净额更新订单状态。awaiting_supplement 状态不能完成（409）。
  - 拒绝：释放当前占用；accepted 与 awaiting_supplement 状态均可拒绝。必须记录可区分的拒绝原因码：amount_exceeds（金额超限）、order_state（订单状态不允许）、request_conflict（请求冲突）、internal_error（内部错误）。拒绝与内部错误不得混为一类。
  - 完成/拒绝均为终态；对终态单据重复调用完成（或拒绝）按幂等重放处理，跨终态迁移被拒绝；终态单据不能退回补件。
  - 每次退回补件与补件通过都必须留下可按退款单标识查询、最新在前的记录，含补件事由码、说明、补件前后金额与发生时间；重放不得新增记录，失败不得写入记录。

## 金额守恒

- 任意时刻对每张订单成立：
  - refunded_cents + pending_refund_cents ≤ paid_cents ≤ amount_cents
  - 未收金额 outstanding_cents = amount_cents − paid_cents
  - 净额 net_cents = paid_cents − refunded_cents
- 任何会使上述恒等式不成立的退款必须整体拒绝（回滚整个事务），不得留下半生效状态或半额占用。
- 订单状态随净额变化：
  - 净额等于订单金额 → settled（结清）
  - 曾收过款且净额为零 → open（回到未结清，可继续收款）
  - 其余（含从未收款、净额介于零与订单金额之间）→ accepted

## 并发与可重放

- 所有写操作在单库写事务（BEGIN IMMEDIATE）内完成；并发提交同一退款请求标识时恰好受理一次，其余提交得到与首次一致的结果。
- 并发对同一退款单发起退回补件或补件提交时恰好生效一次，其余请求得到与首次一致的结果（重放）；任何一次退回或补件失败都整体回滚，不留下半生效状态。
- 收款与退款交替进行后，读取订单与退款单必须得到可解释且可重放的同一结论；中途失败（冲突、金额超限等）不得改变任何已存在单据的金额与状态。
