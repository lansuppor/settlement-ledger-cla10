# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 受理请求必须携带非空幂等键 `idempotency_key` 与非空请求指纹 `request_fingerprint`；缺失任一参数按参数不合法拒绝，不落任何数据。
- 幂等键以（租户, 幂等键）唯一，与订单标识的唯一性相互独立；两类唯一冲突必须可区分（订单标识冲突：`order already accepted`；幂等键冲突：`idempotency key reused with different request fingerprint`）。
- 同一（租户, 幂等键）再次到达时：指纹与首次记录一致视为同一业务请求的重放，返回首次受理的订单对象与相同成功状态（201，响应头 `X-Idempotent-Replay: true`），不新建订单、不改变已有订单与已登记收款；指纹不同则拒绝，且不得覆盖首次受理的订单、金额、币种或收款记录。
- 受理、幂等判定与指纹登记在同一数据库事务内完成：并发下相同幂等键只允许一笔真正受理；受理过程中崩溃不会留下半笔数据，重启后用同一幂等键重试得到与未崩溃时一致的结论。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额；收款登记不受幂等键机制影响。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。
