# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款

- 退款请求标识（`refund_request_id`）由客户端提供，租户内唯一，是退款请求的唯一去重身份；不得用订单标识替代。
- 退款币种沿用原订单币种；退款金额为最小货币单位正整数。
- 不允许对不存在、不属于本租户或已被拒绝的订单发起退款；前两者按 404 处理，不泄漏对象是否存在。
- 同一（租户, 请求标识）重复提交：内容一致时重放首次结果（201 → 200），不重复受理；内容不一致（不同订单或不同金额）按 `request_conflict` 冲突拒绝，不改写首次单据。
- 退款单三阶段：`accepted`（受理：记入未决退款并阻止影响守恒的后续操作）、`completed`（完成：未决占额转入已退、更新净额与状态）、`rejected`（拒绝：释放未决占额）。
- 拒绝原因可区分：`amount_exceeds_paid`（金额超限）、`order_status_rejected`（订单状态不允许）、`operator_rejected`（操作员拒绝，缺省值）、`request_conflict` / `invalid_refund_status`（接口层冲突，不落单据）；业务拒绝与内部错误（5xx）严格区分。
- 任一时刻金额守恒：`已退（含未决占额） ≤ 已收`，`未收 = 订单金额 − 已收`，`净额 = 已收 − 已退`；使守恒式不成立的退款整体拒绝，无半生效状态。
- 订单状态随净额变化：净额为零且曾收过款时为 `unsettled`（未结清）；净额等于订单金额时为 `settled`（结清）。
