# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 受理请求携带幂等键与请求指纹，幂等键以（租户, 幂等键）唯一，与订单标识唯一性相互独立：
  - 同键同指纹视为同一业务请求重放：不新建订单、不改变订单与收款，返回首次受理的订单对象与相同成功状态。
  - 同键不同指纹视为幂等键被复用给不同业务内容，必须拒绝，且不得覆盖首次受理的订单、金额、币种或收款。
  - 两类唯一冲突必须可区分：订单标识重复为 409，指纹冲突为 422；缺幂等键或指纹按参数不合法 400 拒绝，不落数据。
  - 判定在并发与重启后仍成立：同键并发仅一笔真正受理；受理事务提交前崩溃不留记录，重启后同键重试等价于首次受理。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。收款登记不受幂等键机制影响。
- 每笔收款由服务分配收款记录标识 `payment_id`（同租户内唯一、稳定不变，不由调用方指定），可按标识回读。
- 收款可被冲正，用于重复扣款、误收或业务取消时把已登记收款安全抵回：
  - 冲正请求携带非空冲正标识 `reversal_id` 与非空请求指纹 `request_fingerprint`；缺少任一字段按参数不合法 400 拒绝，不落任何数据。
  - 冲正标识以（租户, 冲正标识）唯一，与收款记录标识的（租户, payment_id）唯一性相互独立。
  - 同标识同指纹视为同一业务请求重放：不重复抵回金额，返回首次冲正的结果快照与相同成功状态（响应头标记重放）。
  - 同标识不同指纹视为冲正标识被复用给不同业务内容：422 拒绝，不得覆盖首次冲正记录或已登记收款。
  - 冲正成功后已收金额减少相应金额、未收金额相应回升；订单状态按未收重算：未收清零为已结清，否则回到受理态。任一时刻应收恒等于已收加未收。
  - 冲正本身不可再被冲正：对已冲正收款再次冲正（即便使用新冲正标识）按已处理 409 拒绝；与指纹冲突 422 明确可区分。
  - 收款不存在（含跨租户）一律按不存在 404 处理，不改变订单与收款，也不消耗冲正标识。
  - 冲正为单事务原子写入：两个对同一收款的并发冲正仅一笔真正生效，另一笔按重放或冲突规则给出确定结论；提交前崩溃整体回滚，重启后以同一冲正标识重试结论与未崩溃时一致。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。
- 订单可批量受理：一次提交一组订单资料，每行字段与单笔受理一致（租户、订单标识、订单金额、币种、行幂等键、行请求指纹），批次另携带批次标识与批次请求指纹（均为非空字符串，后者由调用方对整批内容做稳定摘要）：
  - 批次标识唯一范围为（租户, 批次标识），与每行的（租户, 幂等键）、（租户, 订单标识）唯一性相互独立；批次指纹冲突、行指纹冲突、订单重复必须可区分，不归为同一类错误。
  - 批次按指纹判定重复：同批次标识同指纹视为重放，不重复受理任何一行，返回首次导入的结果清单与相同成功状态并标记重放；同批次标识不同指纹视为标识被复用于不同业务内容，必须拒绝（422），且不得覆盖首次导入的任何订单、行结果与批次记录。缺少批次标识或指纹（含空串）按参数不合法 400 拒绝，不落任何数据。
  - 批次内逐行受理，每行遵循单笔受理规则：行内缺幂等键或指纹（含空串、金额/币种/租户非法）为本行参数不合法；同键同指纹为重放；同键不同指纹为指纹冲突；订单标识重复为订单重复。行级拒绝只影响本行，不回滚其他已合格行，也不改动该行已有订单与收款；至少一行合格即部分成功，全部不合格即全部失败。
  - 每行结论（成功 accepted、重放 replayed、各拒绝原因 rejected_invalid / rejected_fingerprint / rejected_duplicate）在批次结果清单中按行号定位；计数闭合：成功数 + 重放数 + 各拒绝数 = 总行数；成功与重放行与其实际落库的订单一一对应（拒绝行无订单落库），清单结论与存储实际状态一致。
  - 可续跑：批次中断时已逐行提交的行保持已受理，未处理的行不留半笔数据；用同一（租户, 批次标识）与同一指纹重新提交，只补做尚未受理的行，已受理行按重放返回首次结果，最终结论与一次性完整导入一致。每行订单与其行级幂等记录、行结论在同一事务内原子提交；并发下同一（租户, 批次标识）只允许一批真正导入，另一批按重放或冲突规则给出确定结论。
  - 批量受理不改变单笔受理入口与响应。
