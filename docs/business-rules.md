# 业务规则

## 订单与收款

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款单

- 退款请求标识（refund_request_id）由客户端提供，在（租户, 请求标识）内唯一，用于请求去重；它与订单标识、退款单业务标识是三个相互独立的身份，不得用订单标识充当请求去重身份。
- 退款金额必须为大于零的整数，币种沿用原订单币种。
- 不允许对不存在、不属于本租户或已被拒绝（order.status='rejected'）的订单发起退款；跨租户一律按不存在处理。
- 同一（租户, 退款请求标识）重复提交：
  - 内容（订单、金额）与首次一致：返回首次受理的退款单，不重复受理、不重复占额（首次 201，重放 200）。
  - 内容与首次不同（指向不同订单或不同金额）：以 request_conflict 拒绝，首次单据的金额与状态不得被改写。
- 退款单生命周期：accepted（受理）→ completed（完成）/ rejected（拒绝）。
  - 受理：金额计入订单的未决退款占用 pending_refund_cents，并阻止会破坏守恒的后续退款。
  - 完成：占用额转入累计已退 refunded_cents，冲减净额并按净额更新订单状态。
  - 拒绝：释放未决占用；必须记录可区分的拒绝原因码：amount_exceeds（金额超限）、order_state（订单状态不允许）、request_conflict（请求冲突）、internal_error（内部错误）。拒绝与内部错误不得混为一类。
  - 完成/拒绝均为终态；对终态单据重复调用完成（或拒绝）按幂等重放处理，跨终态迁移被拒绝。

## 收款计划

- 订单受理后、登记任何收款之前，可以为订单建立一份分期收款计划；计划由若干期组成，每期给出期次标识（installment_id）与本期金额（amount_cents）。
- 建立计划的约束（任一不满足整体拒绝、不写入任何期次）：
  - 订单尚未收到任何款项（paid_cents = 0）；
  - 订单当前不存在收款计划（重复建立拒绝）；
  - 期次标识在该订单内唯一，且非空；
  - 每期金额必须为大于零的整数；
  - 全部期次金额之和必须严格等于订单金额；币种沿用订单。
- 取消收款计划仅在订单未收到任何款项时允许；取消后订单回到无计划状态，可以重新建立计划。无计划可取消时拒绝。
- 计划建立或取消不改变订单的未收金额、已收金额与订单状态。
- 计划存在后，登记收款按期推进：每期累计登记的收款额满本期金额即视该期收讫；一次收款可以跨期生效，先补足当前未收讫期次的剩余部分，再依次计入后续期次。
- 一次登记金额必须等于从当前未收讫期次起若干个连续期次的剩余金额合计（一次收满一期或多期），不得留下不足一期的零头；不满足时整体拒绝（409），订单金额与各期进度均不改变。
- 查询计划返回每期标识、本期金额、本期已收金额、是否收讫，并给出订单整体已计划金额与已收讫期数；订单不存在、跨租户或无计划均按“不存在”处理，不泄漏对象是否存在。

## 金额守恒

- 任意时刻对每张订单成立：
  - refunded_cents + pending_refund_cents ≤ paid_cents ≤ amount_cents
  - 未收金额 outstanding_cents = amount_cents − paid_cents
  - 净额 net_cents = paid_cents − refunded_cents
- 任何会使上述恒等式不成立的退款必须整体拒绝（回滚整个事务），不得留下半生效状态或半额占用。
- 存在收款计划时，已收金额等于各期本期已收金额之和，且等于已收讫各期金额之和；计划总金额等于订单金额。
- 订单状态随净额变化：
  - 净额等于订单金额 → settled（结清）
  - 曾收过款且净额为零 → open（回到未结清，可继续收款）
  - 其余（含从未收款、净额介于零与订单金额之间）→ accepted

## 并发与可重放

- 所有写操作在单库写事务（BEGIN IMMEDIATE）内完成；并发提交同一退款请求标识时恰好受理一次，其余提交得到与首次一致的结果。
- 收款与退款交替进行后，读取订单与退款单必须得到可解释且可重放的同一结论；中途失败（冲突、金额超限等）不得改变任何已存在单据的金额与状态。
