# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 受理请求携带幂等键与请求指纹，幂等键以（租户, 幂等键）唯一，与订单标识唯一性相互独立：
  - 同键同指纹视为同一业务请求重放：不新建订单、不改变订单与收款，返回首次受理的订单对象与相同成功状态。
  - 同键不同指纹视为幂等键被复用给不同业务内容，必须拒绝，且不得覆盖首次受理的订单、金额、币种或收款。
  - 两类唯一冲突必须可区分：订单标识重复为 409，指纹冲突为 422；缺幂等键或指纹按参数不合法 400 拒绝，不落数据。
  - 判定在并发与重启后仍成立：同键并发仅一笔真正受理；受理事务提交前崩溃不留记录，重启后同键重试等价于首次受理。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。收款登记不受幂等键机制影响。
- 每笔收款在登记事务内由服务分配收款记录标识 `payment_id`（同租户内唯一且稳定不变，不由调用方指定，可随登记结果回读）。
- 收款冲正作用于某笔已登记收款，请求携带冲正标识 `reversal_id` 与请求指纹 `request_fingerprint`（均为非空字符串；缺失或空串按参数不合法 400 拒绝，不落任何数据）：
  - 冲正标识唯一范围为（租户, 冲正标识），与收款记录标识的（租户, payment_id）唯一性相互独立。
  - 首次冲正：订单已收减少该笔金额、未收相应回升；订单状态按未收重新核算，未收清零（已收回到全额应收）为已结清，否则回到受理态。
  - 同冲正标识同指纹视为同一业务请求重放：不重复抵回任何金额，返回首次冲正的结果快照；同冲正标识不同指纹必须拒绝（422），且不得覆盖首次冲正记录或已登记收款。
  - 冲正本身不可再被冲正：对已冲正收款以新冲正标识再次冲正按已处理拒绝（409），与指纹冲突（422）明确可区分。
  - 对不存在的收款记录（含跨租户）发起冲正按不存在（404）处理，不改变订单与收款。
  - 冲正与订单更新为单事务原子写入：任一时刻应收恒等于已收加未收；同一收款的两个并发冲正仅一笔真正生效，另一笔按重放或冲突/已处理规则给出确定结论；冲正事务提交前崩溃不留记录，重启后用同一冲正标识重试，结论与未崩溃时一致。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。
